起点：写一个专门给VRChat/Steam玩家的博客

感谢Codex

#wblog#VRChat#Coding Agent#Astro

从一张合照开始

wblog 最早的念头，来自一次和 VRChat 好友的线下面基。那次见面的时候，大家用手机打开 VRCM 把大家的主页面聚到一起，拍了一张属于我们的合照。整理照片的时候，我忽然在想：有没有一个 Web 应用，可以像搭建自己的 VRChat 世界一样自由，把照片、文字、游戏经历和社交身份都放进同一个空间？

普通博客很适合写文章，但我想要的似乎不只是一条按时间排列的文章列表。它应该更像一个人在互联网上的房间：足够私人，也足够开放；能认真写长文，也能随手放下一张照片；还可以展示我最近在玩的游戏、去过的 VRChat 世界，以及散落在不同平台上的生活痕迹。

这个想法当时没有立刻变成项目，却一直留了下来。

从 ChatGPT 3.5 到 Coding Agent

我几乎是一路看着生成式 AI 和 Coding Agent 长大的。

大四做毕业设计时，我还只是在网页上用 ChatGPT 3.5 帮忙写一些代码。研一刚入学的时候，我其实完全不会机器学习，很多概念、实验和报错，也都是靠着一轮轮和 GPT 对话才慢慢弄懂。那时使用 AI 的方式仍然主要是复制问题、粘贴代码，再由自己把零散的回答拼到一起。

后来各种模型、编辑器和 Coding Plan 越来越多，我基本都积极体验过。直到今天，Agent 已经不只是给出一段代码，而是能够自己阅读项目、制定步骤、修改文件、运行测试，并在一次任务中持续工作很久。

尤其是从 Claude Code 换到 Codex 之后，这种感受变得很明显：有时只需要交代一句目标，它就能连续运行很久，最后给出一个完成度相当高的成品。我想这既得益于 sol 本身很强，也得益于 Codex 内置的许多 Skill，以及后训练阶段对工具和 Skill 调用的专门优化。对一个没有前端知识、没有实习经历，也没有真正参与过前后端工程项目的人来说，这种能力非常震撼——一些过去只能停留在想法里的东西，现在终于可以亲手做出来了。

动车上的五小时

最近我经常往返合肥和温州，在动车上度过了很多时间。有一次，我和土豆（VRChat 里的砂糖，也是我的男朋友）聊到，是不是可以把自己的博客彻底重构一下。

于是我打开 Codex，从那个留下很久的念头开始描述：我想要一个以内容为核心、能够高度自定义，同时又更贴近 VRChat 玩家的个人网站。大约五个小时之后，wblog 的第一个版本就已经可以运行了。

它目前使用 Astro 构建静态页面，文章、生活记录和相册都保存在本地 Markdown 与图片目录中。网站不依赖常驻后端，可以直接部署到 GitHub Pages；VRChat 数据则通过命令行登录，在构建前调用 API，把公开资料、头像和最近访问的世界整理成本地快照。即使 API 暂时不可用，网站也能继续使用上一份有效数据完成构建。

这种实现方式也是我很看重的一点：数据首先属于站点拥有者，构建结果只是静态文件。账号凭据不会进入页面，也不需要为了一个个人主页维护复杂的服务器。想换配色、改布局、增加栏目，或者接入新的平台时，又依然保留了足够大的修改空间。

不只是一篇篇博客

wblog 面向的用户画像其实很具体：可能和我一样，是学计算机、玩 Steam、看 B 站，也把很多时间和记忆留在 VRChat 里的二次元玩家。

我们在不同平台上有很多身份，但它们很少真正聚在一起。博客记录思考，相册保存瞬间，Steam 展示游戏，B 站收藏兴趣，VRChat 则承载朋友、世界和共同经历。我希望 wblog 能把这些内容连接起来，最终成为一个真正属于自己的个人 Hub。

所以它不只是“又一个博客主题”。博客只是其中的一部分，Gallery、Life、VRChat，以及未来可能出现的更多模块，共同组成一个人在网络上的展示界面。它可以很简洁，也可以很宅；可以作为作品集，也可以只是朋友们偶尔来坐坐的小房间。

这就是 wblog 的起点。它还远远没有完成，但能够把曾经的一张合照、几年里对 AI 的好奇，以及动车上的一次聊天，慢慢变成一个真实可访问的网站，本身就已经是一件很开心的事。
